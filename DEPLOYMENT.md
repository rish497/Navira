# Deploy NAVIRA on Render for $0

NAVIRA runs as a free Render Web Service. Because Render deletes local files when
a free service sleeps, restarts, or redeploys, NAVIRA stores authentication and
operational records in a free Upstash Redis database when its REST credentials
are configured.

## 1. Create the free persistent store

1. Create an account at https://console.upstash.com/.
2. Create one Redis database on the Free plan.
3. Open the database's **REST API** section.
4. Copy the **UPSTASH_REDIS_REST_URL** and **UPSTASH_REDIS_REST_TOKEN** values.

Keep the token private. It is a server credential and must never be prefixed
with `VITE_` or committed to Git.

## 2. Create the free Render service

1. Open https://dashboard.render.com/.
2. Choose **New > Blueprint**.
3. Connect GitHub and select `rish497/Navira`.
4. Render will detect `render.yaml` and create the `navira` free Web Service.
5. Supply these secret values when prompted:
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`
   - `YOLO_AUTO_API_KEY`
6. Apply the Blueprint and wait for the deploy to become live.

`NAVIRA_AUTH_PEPPER` is generated by Render. Do not change it after users have
registered, because changing it invalidates existing password hashes.

## 3. Verify the deployment

Open the generated `onrender.com` address and verify:

- `/`
- `/login?role=civilian`
- `/login?role=operator`
- `/api/live-events`

The free service sleeps after a period without traffic and can take about a
minute to wake. Authentication and operational records remain in Upstash.

## Free-tier limits

- Render free services sleep after inactivity and have monthly bandwidth/build
  limits.
- Upstash Free currently provides a limited command, bandwidth, and storage
  allowance suitable for a prototype.
- This setup is for prototype and evaluation use. A public emergency service
  requires paid infrastructure, monitoring, backups, and a production server.
